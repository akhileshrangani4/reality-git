# Native splat renderer notes

Verified September 8, 2026: the iPhone 15 Pro build now renders captured depth points using iOS 27's native `GaussianSplatComponent` and `GaussianSplatResource`. The user confirmed seeing the remembered shape on the phone. This validates the preview, not movement, restoration, or measured anchor accuracy.

The MVP freezes a first-view LiDAR surface with sampled camera colors, capped at 8,000 points. It renders small isotropic Gaussians with 25% opacity and red/green tint. This is a partial visible surface, not an optimized multi-view reconstruction. The original cloud and world position survive tracking loss and reselection; “Start over” clears them. The preview toggle displays the saved red shape independently of the automatic diff.

Capture uses a foreground mask or a depth component separated from background around the selected rectangle. Commit `52a9d7e` moves the fallback's background sampling outside tight selections, while keeping captured points inside the selection. Follow-up `cd4728e` accounts for slanted background planes at image edges. These corrections have passed build, regression tests, and independent review and are installed as part of `9ecf7f4`.

Fresh depth components can now follow relocation along camera depth after size, color, and normalized-support association checks. The signature uses the current tracking rectangle consistently across mask and depth paths. Reused support from an older segmentation retains the stricter prior-depth guard. These checks preserve the reference cloud while updating the current position; physical green-overlay and restoration verification remains pending.

Current build `dd16c9e` also permits a known object's coherent depth component when its outer background is not visible. Initial capture still requires background separation; a later candidate must match the existing signature. This association is approximate: similarly colored and shaped surfaces can remain ambiguous. When current 3D geometry is missing after a confirmed change, the app can show a translucent green rectangle on a fresh trusted local image track. That fallback does not supply a world position or alter diff state, and it expires with tracking freshness. The red captured ghost remains anchored in world coordinates.

Apple's [component documentation](https://developer.apple.com/documentation/realitykit/gaussiansplatcomponent) supplies a buffer-based example and specifies Apple7 GPU-family support. The renderer expects positions, scale, quaternion rotation, opacity and spherical-harmonic coefficients; the app must parse its asset format. Quaternion buffer order is scalar first (`r, x, y, z`), so do not copy SIMD quaternion storage blindly.

Use explicit offsets and strides, and align `LowLevelBuffer` capacity as required. Resource creation can throw for invalid descriptors or excessive splat counts. Keep the proxy on failure. The renderer blends transparent splats and does not require an app-authored shader. Uniform ghost tint must be applied to appearance data rather than a mesh material. [GaussianSplatResource](https://developer.apple.com/documentation/realitykit/gaussiansplatresource) exposes scale/opacity activation controls; match those to the asset's representation to avoid applying exponentials or sigmoid twice.

The current buffer uses scalar-first identity quaternions, explicit metric scales, identity scale/opacity activations, and degree-zero spherical-harmonic colors. Resource creation failures show an explicit proxy fallback status. Phone logs confirmed native resources with 846 and 1,536 captured points. Quantitative alignment, opacity, depth interaction, larger budgets, and the automatic move/remove/restore cycle still need physical validation.
